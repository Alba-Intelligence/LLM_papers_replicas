# Data Model: Julia Replication Project

**Date**: 2026-01-16  
**Purpose**: Define data structures and entities for Julia package replication

## Core Entities

### 1. Hypergraph

**Description**: Primary data structure representing higher-order relationships among multiple entities.

**Attributes**:
- `nodes`: Set of node identifiers (strings or integers)
- `edges`: Set of hyperedges, where each hyperedge is a set of nodes
- `edge_properties`: Dictionary mapping edge IDs to metadata (source, target, relation, chunk_id)
- `node_attributes`: Dictionary mapping node IDs to attributes (type, embeddings, etc.)

**Relationships**:
- Contains multiple nodes
- Contains multiple hyperedges
- Each hyperedge connects multiple nodes

**Validation Rules**:
- Nodes must be unique identifiers
- Hyperedges must contain at least one node
- Edge properties must reference valid edge IDs

**State Transitions**:
- Created from text via `hypergraphPrompt()` or `make_hypergraph_from_text()`
- Updated via union operations (`add_new_hypersubgraph_from_text()`)
- Simplified via `simplify_hypergraph()` (merges similar nodes)
- Pruned via `remove_small_hyperfragments()` (removes small components)

**Julia Implementation**:
- Use `Hypergraphs.jl` `Hypergraph` type
- Edge properties stored as DataFrame or Dict
- Node attributes stored as Dict

---

### 2. Node Embeddings

**Description**: Vector representations of nodes for similarity computation and path finding.

**Attributes**:
- `node_id`: String identifier for the node
- `embedding_vector`: Array of floats (embedding dimensions vary by model)
- `model_name`: String identifying the embedding model used

**Relationships**:
- One-to-one with Hypergraph nodes
- Generated by embedding models (Transformers.jl or sentence-transformers equivalent)

**Validation Rules**:
- Embedding vectors must have consistent dimensionality for a given model
- Node IDs must match nodes in associated hypergraph

**State Transitions**:
- Generated via `generate_hypernode_embeddings()`
- Updated when hypergraph is modified (new nodes added)
- Pruned when nodes are removed from hypergraph

**Julia Implementation**:
- Dict mapping node_id → Vector{Float32} or Matrix{Float32}
- Store model metadata separately

---

### 3. Text Chunk

**Description**: Segmented text input used for hypergraph generation.

**Attributes**:
- `chunk_id`: String (MD5 hash of chunk text)
- `text`: String content
- `chunk_index`: Integer position in document
- `metadata`: Dict with additional information (source document, etc.)

**Relationships**:
- Multiple chunks processed to generate one hypergraph
- Each chunk may generate multiple hyperedges

**Validation Rules**:
- Chunk ID must be unique
- Text must be non-empty
- Chunk index must be non-negative

**Julia Implementation**:
- DataFrame with columns: `chunk_id`, `text`, `chunk_index`, `metadata`
- Or custom struct `TextChunk`

---

### 4. Hypergraph Sub-DataFrame

**Description**: DataFrame storing hyperedge metadata (source, target, relation, chunk).

**Attributes**:
- `edge`: String edge identifier
- `nodes`: Set of node identifiers in the hyperedge
- `source`: List of source nodes
- `target`: List of target nodes
- `chunk`: String chunk_id that generated this edge

**Relationships**:
- One row per hyperedge
- Links to TextChunk via chunk_id
- Links to Hypergraph via edge ID

**Validation Rules**:
- Edge IDs must be unique
- Source and target must be subsets of nodes
- Chunk must reference valid chunk_id

**Julia Implementation**:
- DataFrame with columns: `edge`, `nodes`, `source`, `target`, `chunk`
- Indexed by `edge` column

---

### 5. Graph (Traditional, Non-Hypergraph)

**Description**: Directed graph representation (NetworkX DiGraph equivalent) for some operations.

**Attributes**:
- `nodes`: Set of node identifiers
- `edges`: List of (source, target) tuples
- `edge_attributes`: Dict mapping (source, target) to metadata (relation, chunk_id, title)
- `node_attributes`: Dict mapping node IDs to attributes (type, texts, etc.)

**Relationships**:
- Alternative representation to hypergraph
- Can be converted from/to hypergraph

**Validation Rules**:
- Edges must reference valid nodes
- Edge attributes must reference valid edges

**Julia Implementation**:
- Use `Graphs.jl` `DiGraph` type
- Attributes stored as separate Dict structures

---

### 5. Pluto Notebook

**Description**: Converted Julia notebook that replicates functionality from a Python Jupyter notebook.

**Attributes**:
- `file_path`: String path to notebook file (`.jl` file in notebooks/ directory)
- `original_notebook`: String name of original Python notebook (`.ipynb` file)
- `cells`: Vector of reactive cells (code, markdown, or output)
- `dependencies`: Vector of package names used via `using` statements
- `execution_state`: Execution status (not executed, executing, completed, error)
- `outputs`: Dictionary mapping cell IDs to outputs (data, visualizations, text)

**Relationships**:
- Uses the top-level Julia packages (via `using` statements)
- May generate Hypergraph, Node Embeddings, or other entities
- May read/write data files (JLD2, JSON, CSV)

**Validation Rules**:
- Must be valid Pluto notebook format (`.jl` file with cell structure)
- All `using` statements must reference available packages
- Must execute without errors (for successful conversion validation)
- Outputs should match Python notebook outputs (within tolerance for floating-point)

**State Transitions**:
- Created via conversion from Python Jupyter notebook
- Executed via Pluto.jl (reactive execution)
- Updated when source Python notebook changes (re-conversion needed)

**Julia Implementation**:
- Use `Pluto.jl` for execution
- Store as `.jl` files in `notebooks/` directory
- Dependencies managed via `using` statements within notebook
- Pluto automatically creates/manages Project.toml for notebook environment

## Data Flow

1. **Text Input** → Text Chunks (via text splitting)
2. **Text Chunks** → Hypergraph (via LLM extraction)
3. **Hypergraph** → Node Embeddings (via embedding model)
4. **Hypergraph + Embeddings** → Analysis Results (path finding, centrality, etc.)
5. **Hypergraph** → Serialization (JLD2/JSON/GraphML for persistence)

## Serialization Formats

- **JLD2**: Primary format for Julia-native serialization (hypergraphs, embeddings)
- **JSON**: Interoperability format (can be read by Python for comparison)
- **GraphML**: Graph export format (for visualization tools)
- **CSV**: Tabular data (chunks, edge metadata)

## Data Validation

- Hypergraph consistency: All edge nodes must exist in node set
- Embedding consistency: All embedding node IDs must exist in hypergraph
- Chunk consistency: All edge chunk references must exist in chunk set
